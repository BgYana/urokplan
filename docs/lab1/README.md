# Техническое задание первой лабораторной


| Область | Требования | Что должно работать |
|---|---|---|
| Аккаунты | AUTH-01–04 | Регистрация, вход, выход, роли, публичный ID, защищённые API |
| Связи | REL-01–04 | Приглашения преподавателя и ученика, привязка родителя, отзыв доступа |
| Курсы | CRS-01–04 | Создание курса, включение ученика, персональный тариф, отдельный учёт единиц |
| Группы | GRP-01–02 | Состав группы, применение изменений к будущим занятиям, изоляция персональных данных |
| Расписание | SCH-01–11 | Разовые и еженедельные занятия, перенос одного или последующих, отмена, конфликты и посещение |
| Оплата | PAY-01–15 | Заявки и подтверждения, ручная регистрация, остаток, предварительное покрытие, списания, долги и корректировки |
| ДЗ | HW-01–06 | Выдача, черновик, сдача, проверка, доработка и история попыток |
| Вложения | FILE-01–04 | JPEG, PNG и PDF у преподавателя и ученика; загрузка и защищённое скачивание |
| Оценки | ASMT-01 | Оценка преподавателя 0–10, история и среднее |
| Обратная связь | FB-01–04 | Настроение и сложность 1–5, необязательный комментарий, приватность |
| Уведомления | NOT-01–03 | Внутренний список, прочтение, надёжное сохранение событий |
| Видеосвязь | VID-01 | Хранение постоянной ссылки и переопределения у занятия |
| Качество | NFR-01–09 | Права, транзакции, документация API, воспроизводимые миграции и тесты |

Хранение ссылки на видеосервис проверяется через API. Кнопка подключения относится к будущему клиенту.

## За пределами лабораторной

- Desktop- и Android-клиенты, пользовательские экраны и системные push.
- Подтверждение почты и восстановление через email.

- Рассылки MSG-01, автоматические напоминания NOT-04–07 и Telegram.
- Настраиваемые критерии ASMT-02, графики FB-05 и ANA-01.
- Приём банковских платежей, денежный баланс, частичные единицы, переводы единиц между курсами.
- Отдельные микросервисы, брокер сообщений и production-развёртывание.

## Реализация

### 1 Структура

Один исполняемый модуль `server/app` собирает предметные Gradle-модули `identity`, `relationships`, `courses`, `scheduling`, `billing`, `learning`, `files`, `notifications`. Общая инфраструктура БД ограничена подключением, транзакционной абстракцией и запуском миграций. SQL-таблицы и репозитории принадлежат предметным модулям.


### 2 Данные и миграции


- Liquibase применяет корневой changelog, который явно подключает миграции модулей в нужном порядке.
- Чистая БД создаётся миграциями. Повторный запуск не повторяет изменения. Изменение уже применённой миграции заменяется новой миграцией.
- Логические схемы или префиксы таблиц отражают владельца данных. Другой модуль не читает их напрямую.
- Для денег используются точные значения минимальных единиц валюты; для оплаченных занятий — целые единицы.
- Все бизнес-операции задают границу транзакции. Репозитории не создают несогласованные независимые транзакции внутри одного сценария.
- Ограничения и блокировки защищают от двойных пополнений и списаний.

### 3 План маршрутов


| Группа | Примеры маршрутов | Основные операции |
|---|---|---|
| Аккаунт | `/auth/register`, `/auth/login`, `/auth/logout`, `/me` | Регистрация, сессии и профиль |
| Поиск | `/users/by-public-id/{id}` | Минимальный профиль |
| Связи | `/connection-requests`, `/guardian-requests` | Создание, решение, прекращение связи |
| Курсы | `/courses`, `/courses/{id}/enrollments` | Курс, участники и цены |
| Группы | `/groups`, `/groups/{id}/members` | Состав группы |
| Расписание | `/lessons`, `/lesson-series` | Календарь, создание и изменение |
| Посещение | `/lessons/{id}/participants/{studentId}/attendance` | Персональная отметка и исправление |
| Оплата | `/payment-claims`, `/payment-claims/{id}/confirm`, `/payment-claims/{id}/reject` | Заявки и решения |
| Ручная оплата | `/courses/{id}/students/{studentId}/payments` | Подтверждённая регистрация преподавателем |
| Состояние оплаты | `/courses/{id}/students/{studentId}/payment-summary` | Остаток, ожидающие единицы, долги и история |
| Прогноз | `/courses/{id}/students/{studentId}/payment-preview` | Покрытие при покупке N единиц без закрепления будущих занятий |
| ДЗ | `/assignments`, `/assignments/{id}/submissions` | Задания и попытки |
| Проверка | `/submissions/{id}/review` | Оценка, комментарий и доработка |
| Файлы | `/files`, `/files/{id}/content` | Загрузка и защищённое скачивание |
| Оценки | `/lessons/{id}/participants/{studentId}/assessment` | Учебная оценка |
| Личный отзыв | `/lessons/{id}/feedback` | Настроение, сложность и комментарий автора |
| Уведомления | `/notifications`, `/notifications/{id}/read` | Список и прочтение |

В реальном контракте все маршруты получают префикс `/api/`. Swagger UI работает с теми же предметными API.


## Автоматические проверки

| Уровень | Обязательные группы |
|---|---|
| Юнит | Правила единиц и покрытия, статусы заявок, допустимость посещения, шкалы, права приватного отзыва |
| Интеграция с PostgreSQL | Liquibase, атомарность, конкуренция заявок/списаний, конфликты расписания|
| API | Аутентификация, все роли, отрицательные права, корректность DTO, ошибки и multipart |
| Файловая интеграция | Ограничения, серверные имена, недоступность чужих файлов, очистка незавершённых загрузок |

Время подменяется через `Clock`. Реальные ожидания дедлайнов в тестах не используются. Внешних банковских, Telegram- и push-вызовов в этой лабораторной нет.
